# 무료 공유자료: 참석 여부(RSVP) 설정 안내

## 현재 사이트 상태

- 메인 일러스트 카드와 마지막 화면의 참석 버튼은 같은 참석 안내 팝업을 연다.
- 팝업의 참석 전달 버튼은 `config.js`의 `rsvpUrl`에 지정한 폼을 새 탭으로 연다.
- 현재 URL은 비어 있어 준비 중 안내만 나온다. 응답을 수집하거나 저장하지 않는다.
- 입력 화면만 구현해 놓고 실제 전달이 되었다고 표시하면 안 된다.

## 기본 코스 권장: 구글폼 + 구글시트

개인 서버나 DB 없이 응답을 보관할 수 있어 무료 나눔 자료의 기본 경로로 적합하다. 구글폼 화면의 디자인은 청첩장과 다를 수 있다. 사이트 내부의 맞춤 입력폼은 별도 수집/저장 경로가 필요하다.

1. 예비부부가 소유하는 계정으로 구글폼을 만든다.
2. 신랑측/신부측, 참석/불참, 식사 여부, 성함, 동행 인원 등 필요한 질문을 만든다.
3. 연락처, 동행인 이름, 전세버스 질문은 실제 필요할 때만 추가한다. 전세버스가 없으면 묻지 않는다.
4. 불참 선택 시 식사·동행 질문을 건너뛰는 분기를 설정한다. 필수 항목과 선택 항목을 구분한다.
5. 수집 목적, 수집 항목, 보관 기간/파기 시점, 담당 연락처, 동의 거부 시 영향을 명확히 안내한다. 구글 서비스를 통한 처리 내용도 실제 설정과 맞게 확인한다. 예식 후 파기할 날짜를 정한다.
6. 응답 탭에서 예비부부가 소유하는 구글시트로 연결한다. 응답 결과를 외부에 공개하지 않는다.
7. 외부 하객이 응답할 수 있는지 확인한다. 조직 내부 제한, 로그인 요구, 이메일 자동 수집, 파일 업로드 요구는 설정과 실제 응답 흐름에 따라 달라진다. 메뉴명은 자료 작성 시 최신 화면으로 재확인한다.
8. 응답자에게 제공하는 공유 링크를 복사한다. 편집 주소나 응답 시트 주소를 쓰지 않는다.
9. 링크를 `config.js`의 `rsvpUrl`에 넣고 커밋·푸시한다.
10. Netlify에 새 커밋이 게시된 뒤 시크릿 창과 실제 휴대폰에서 링크를 열어 로그인 없이 응답 가능한지 테스트한다.
11. 가짜 테스트 이름으로 참석/불참을 각각 제출하고 구글시트에 실제 저장되는지 확인한다. 테스트 응답을 삭제한다.
12. 예식 후 필요한 자료를 안전하게 백업하고 폼 응답 수집을 종료한다. 정한 기간에 폼·시트의 개인정보와 불필요한 사본을 삭제한다. 사이트만 삭제해도 응답은 남을 수 있다.

## 문제 해결

- 버튼을 눌러 준비 중이라고 뜸: `rsvpUrl`이 비었는지, 최신 커밋이 게시되었는지 확인.
- 로그인 요구: 폼의 응답자 접근 범위와 로그인 관련 질문/설정을 실제 시크릿 창에서 확인.
- 접근 거부: 폼 편집 주소를 공유했거나 조직 내부로 제한했는지 확인.
- 전달한 것 같은데 시트에 없음: 실제 제출 완료 화면과 폼 응답 탭, 연결 시트, 필터를 확인.
- 청첩장 안에 같은 디자인으로 입력받고 싶음: UI 구현 외에 저장소, 서버/수집 서비스 설정, 오류 처리, 운영자 확인 방법이 필요하다. 브라우저 localStorage만으로는 예비부부에게 전달되지 않는다.

## 자료 제작 시 반드시 포함

버튼 클릭 → 폼 입력 → 제출 완료 → 예비부부의 응답 확인까지 캡처한다. 폼 생성, 개인정보 안내, 연결, 모바일 테스트, 예식 후 정리까지 각각 안내한다. 서비스 무료 한도와 외부 접근 설정은 자료 공개 직전에 다시 확인한다.
