# 3. 내 사진·예식 정보로 바꾸기

처음에는 디자인을 그대로 두고 사진과 정보만 바꿉니다. 디자인까지 동시에 바꾸면 무엇 때문에 오류가 났는지 확인하기 어려워집니다.

## 1단계: 이미지 준비

배포용 사진 6장, 컬러 일러스트 1장, 흑백 일러스트 1장, 약도를 준비합니다. 첨부할 때 각각의 용도를 적어 주세요.

| 파일 예시 | 용도 |
|---|---|
| cover.webp | 첫 화면 카드 |
| invitation.webp | 초대글 뒤의 흑백 일러스트 |
| gallery-01.webp ~ gallery-06.webp | 갤러리 사진 |
| map.webp | 약도 |

확장자를 글자로 바꾸지 말고 실제 이미지 내보내기 기능으로 저장하세요. 세로·가로 사진은 원본 비율을 유지합니다. 배경 일러스트는 화면을 채우기 위해 가장자리가 잘릴 수 있습니다.

## 2단계: AI에게 한 번에 전달하기

아래 요청문에 1장에서 채운 정보를 넣고 사진을 첨부합니다. 빈칸은 숨기거나 준비 중으로 남겨달라고 명시하세요.

```text
이 모바일 청첩장 템플릿을 내 사진과 예식 정보로 바꿔줘.
기존 디자인·폰트·모션·섹션 순서는 유지해줘.
내 저장소 사본에서 작업하고, 원본 템플릿은 변경하지 마.

[정보]
신랑 / 신부:
예식일(연·월·일) / 요일:
예식 시간(한국 시간):
장소 / 층 / 홀:
도로명 주소:
초대 문구:
신랑측 은행 / 계좌 / 예금주:
신부측 은행 / 계좌 / 예금주:
지도 링크(네이버 / 카카오 / 티맵):
지하철 / 버스 / 주차 안내:
구글폼 응답자 링크(아직 없으면 미연결):

[첨부 이미지]
카드 이미지:
초대글 배경 이미지:
갤러리 이미지 1~6:
약도 이미지:

실제 파일을 읽은 뒤 수정해줘. 없는 파일이나 빈 정보를 임의로 만들지 마.
사진은 원본 비율을 유지하고, 문구가 얼굴을 가리지 않는지 확인해줘.
config만 바꾸고 끝내지 말고, HTML·JS에 직접 들어간 이름·날짜·시간·달력·참석 안내·메타정보도 찾아 일치시켜줘.
예식일의 요일·달력의 시작 요일·일수·D-day가 한국 시간 기준으로 맞는지 확인해줘.
수정한 파일, 확인한 동작, 미확인·미연결 항목을 구분해 알려줘.
확인하지 못한 것을 확인했다고 말하지 마.
```

AI가 작업 환경에 접근할 수 없다고 하면 파일을 수정했다고 간주하지 마세요. 수정 파일 또는 실제 저장소 변경 내역을 받아 확인합니다.

## 3단계: 정보 확인

- 첫 화면, 달력, 참석 안내의 날짜·시간이 모두 같나요?
- 이름과 장소가 예시값으로 남아 있지 않나요?
- 계좌번호와 예금주가 맞나요?
- 주소 복사와 각 지도 링크가 올바른 장소를 가리키나요?
- 교통·주차 안내가 예식장의 최신 안내와 같나요?
- 참석 링크가 없을 때 전달 완료로 보이지 않나요?

현재 개발 중인 예시는 날짜·시간과 달력 일부가 코드에 직접 들어 있습니다. 배포용 템플릿이 정보 한 파일만으로 갱신되도록 정리됐는지는 공개 전 안내자가 확인해야 합니다. 정리 전에는 ‘config 한 파일만 바꾸면 모두 끝난다’고 안내하지 않습니다.

## 4단계: 변경을 GitHub에 저장

AI가 파일을 바꿨더라도 GitHub에 자동으로 반영됐다고 가정하지 마세요.

```text
수정한 청첩장 파일을 내 저장소에 커밋·푸시해줘.
변경 내용을 먼저 확인하고, 기존 사용자 파일을 지우거나 강제로 덮어쓰지 마.
푸시한 브랜치와 커밋을 알려줘. 푸시 권한이 없으면 필요한 수동 단계를 안내해줘.
```

AI가 푸시하지 못하면 수정 파일을 GitHub에 업로드하고 저장합니다. 메인 파일과 이미지 경로가 최상위 기준으로 맞는지 확인하세요.

## 완료 기준

- [ ] 카드·흑백 일러스트·사진 6장이 내 이미지로 바뀌었다.
- [ ] 날짜·시간·이름이 화면 전체에서 일치한다.
- [ ] 약도와 교통 안내를 확인했다.
- [ ] 변경 내용이 내 GitHub 저장소에 저장됐다.
- [ ] 아직 미연결인 기능을 알고 있다.
