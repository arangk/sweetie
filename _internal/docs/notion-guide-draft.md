# 내 사진으로 완성하는 모바일 청첩장

사진과 예식 정보를 바꿔, 우리만의 청첩장을 만들어 보세요.

이 자료는 완성된 템플릿을 복사해 수정하고, 하객에게 보낼 웹주소를 만드는 안내입니다. 코드를 처음부터 작성할 필요는 없지만 파일 수정과 계정 연결 과정은 있습니다. 막히는 부분은 함께 제공하는 AI 요청문과 문제 해결 안내를 이용하세요.

> 편집 초안입니다. `[완성 예시]`, `[템플릿 받기]` 등 대괄호 링크는 자료 공개 전에 실제 링크로 교체합니다. 아래 기능 안내는 배포용 템플릿의 최종 검증 후 확정합니다.

## 먼저 완성 모습을 확인하세요

[완성 예시 보기 — 공개용 링크 삽입]

- 일러스트 카드와 초대 문구
- 사진 6장 갤러리와 크게 보기
- 예식 날짜·달력·D-day
- 약도와 지도 길찾기
- 계좌 안내·복사

작동하는 예시와 실제 응답 수집 여부는 별개입니다. 본인의 구글폼 연결과 응답 저장 테스트를 마쳐야 참석 기능을 사용할 수 있습니다.

## 이 자료가 잘 맞는 분

- 준비된 디자인에 사진과 정보를 넣어 청첩장을 완성하고 싶은 예비부부

처음부터 디자인하고 싶다면 기본 코스를 먼저 완성한 뒤 심화 코스로 이동하세요.

PC, 휴대폰, 사진·예식 정보, GitHub·Netlify·Google 계정이 필요합니다. 기존 계정을 사용해도 됩니다. 기본 코스는 무료 요금제로 시작하는 구성을 안내합니다. 무료 한도와 이용 조건은 서비스에서 확인하세요. 개인 도메인이나 유료 AI 기능은 필수가 아닙니다.

완성 시간을 보장하지 않습니다. 계정 가입, 이미지 준비와 문제 해결 시간을 여유 있게 잡으세요.

# 1. 사진·정보와 개인정보 준비

작업하기 전에 아래 내용을 한곳에 모아 주세요. 빠진 정보가 있으면 예시값으로 남겨둘 수 있지만 하객에게 공유하기 전에는 반드시 교체해야 합니다.

## 준비물

- PC와 휴대폰
- 본인이 접근할 수 있는 GitHub·Netlify·Google 계정
- 갤러리 사진 6장
- 카드에 넣을 컬러 일러스트와 초대글 배경용 흑백 일러스트
- 약도 이미지 또는 예식장 공식 약도

현재 디자인은 사진 6장을 기준으로 합니다. 사진 수를 바꾸는 것은 심화 수정에 해당합니다. 일러스트가 없다면 사용 권한이 있는 사진으로 대체하거나 심화 코스의 AI 일러스트 작업을 이용할 수 있습니다. AI 이미지 생성은 이 기본 코스의 필수 과정이 아닙니다.

## 복사해서 채울 정보표

| 항목 | 내 정보 |

| 신랑 / 신부 이름 | |

## 사진을 올리기 전에

1. 사진에 나온 사람의 공개 동의를 확인합니다.
2. 배포용 사본을 만들고 원본은 별도로 보관합니다.
3. 웹에서 보기 적절한 크기와 용량으로 줄입니다. 긴 변 1,200~1,600px 정도를 출발점으로 삼고 실제 휴대폰에서 선명도를 확인하세요.
4. EXIF 위치정보를 제거합니다. 사용한 도구에서 제거 여부를 확인하세요. 확장자를 바꾸는 것만으로 제거되지 않습니다.
5. 사진 파일명은 `gallery-01.webp`처럼 단순하게 정리합니다. 사진 내용을 늘이거나 찌그러뜨리지 않습니다.

### AI에게 요청할 때

```text
첨부한 사진의 배포용 사본을 만들어줘.
인물·구도·색을 바꾸지 말고 원본 비율을 유지해 웹용으로 용량을 줄여줘.
EXIF 위치정보를 제거하고 파일별 크기·용량과 실제 확인한 메타데이터 제거 결과를 알려줘.
원본 파일은 덮어쓰지 마.
파일을 읽거나 수정할 수 없는 환경이면 못 했다고 말해줘.
확인하지 못한 것을 확인했다고 말하지 마.
```

AI가 파일을 직접 처리할 수 없는 환경이라면 이미지 편집 도구의 웹용 내보내기 기능을 사용하세요.

## 링크를 아는 사람은 볼 수 있어요

GitHub 저장소를 비공개로 해도 Netlify 사이트를 공개하면 청첩장은 열람할 수 있습니다. 검색 제외 설정도 비밀번호와 같은 접근 제한은 아닙니다.

계좌를 접어두거나 전화번호를 숨겨도 사이트 파일에 포함된 정보는 확인할 수 있습니다. 신혼집 주소·불필요한 연락처·하객 응답을 페이지에 넣지 마세요. 관리자 비밀번호, API 키, 신분증, `.env` 파일도 올리지 않습니다.

## 완료 기준

# 2. 템플릿 복사하기

원본 템플릿은 보존하고, 내 GitHub 계정에 별도 사본을 만들어 작업합니다.

> [템플릿 받기 — 배포용 템플릿 링크 삽입]

## GitHub는 무엇인가요?

청첩장 파일을 보관하고 수정 기록을 남기는 곳입니다. Netlify는 그 파일을 읽어 웹사이트로 배포합니다. GitHub에 저장한 것과 사이트에 게시한 것은 서로 다른 단계입니다.

## 내 사본 만들기

1. GitHub에 가입하거나 로그인합니다.
2. 위 템플릿 링크를 엽니다.
3. 템플릿에서 새 저장소를 만드는 기능을 사용합니다. 실제 버튼명과 화면은 아래 캡처를 참고하세요.
4. 내 계정과 새 저장소 이름을 선택합니다.
5. 개인정보가 들어갈 예정이므로 저장소는 Private으로 만듭니다.
6. 생성된 주소의 소유자가 내 계정인지 확인합니다.

[캡처: 템플릿 버튼 → 새 저장소 생성 → Private → 생성 완료]

공개 템플릿을 그대로 수정하거나, 다른 사람의 저장소에 개인정보를 올리지 마세요. Private 복사가 가능한 배포 경로를 안내자가 사전에 검증한 템플릿을 사용해야 합니다.

## 파일이 있는지 확인하기

최상위 폴더에 다음 파일이 보여야 합니다.

```text
index.html
config.js
app.js
styles.css
assets/
```

README만 보이면 청첩장 파일이 없는 상태입니다. 이 상태로 배포하면 웹페이지가 나오지 않을 수 있습니다.

`index.html`은 첫 화면, `config.js`는 내 정보, `assets`는 사진·폰트가 있는 폴더라고 이해하면 됩니다. GitHub와 Netlify를 연동하는 코스에서는 배포용 ZIP을 따로 올리지 않습니다.

## AI로 수정할 작업 환경 준비

이 자료는 파일을 읽고 수정할 수 있는 AI 작업 환경을 기준으로 합니다. 일반 채팅창은 GitHub의 파일을 직접 고치거나 커밋·푸시하지 못할 수 있습니다.

AI 작업 환경에 내 저장소를 연결하거나 파일을 첨부하세요. 연결할 수 없다면 수정한 파일을 내려받아 GitHub 웹 화면에서 업로드·저장하는 경로를 사용합니다. 구체적인 환경별 화면은 검증된 경로 하나를 선택해 [작업 환경 안내 — 링크 삽입]에 넣습니다.

## 완료 기준

- [ ] 내 계정에 비공개 저장소를 만들었다.
- [ ] 원본과 내 사본의 주소가 다르다.
- [ ] `index.html`과 이미지 폴더가 있다.
- [ ] AI가 내 사본 파일을 읽을 수 있거나 수정 파일을 받을 방법이 있다.

# 3. 내 사진·예식 정보로 바꾸기

처음에는 디자인을 그대로 두고 사진과 정보만 바꿉니다. 디자인까지 동시에 바꾸면 무엇 때문에 오류가 났는지 확인하기 어려워집니다.

## 1단계: 이미지 준비

배포용 사진 6장, 컬러 일러스트 1장, 흑백 일러스트 1장, 약도를 준비합니다. 첨부할 때 각각의 용도를 적어 주세요.

| 파일 예시 | 용도 |
|---|---|
| cover.webp | 첫 화면 카드 |
| invitation.webp | 초대글 뒤의 흑백 일러스트 |
| gallery-01.webp ~ gallery-06.webp | 갤러리 사진 |
| map.webp | 약도 |

확장자를 글자로 바꾸지 말고 실제 이미지 내보내기 기능으로 저장하세요. 세로·가로 사진은 원본 비율을 유지합니다. 배경 일러스트는 화면을 채우기 위해 가장자리가 잘릴 수 있습니다.

## 2단계: AI에게 한 번에 전달하기

아래 요청문에 1장에서 채운 정보를 넣고 사진을 첨부합니다. 빈칸은 숨기거나 준비 중으로 남겨달라고 명시하세요.

```text
이 모바일 청첩장 템플릿을 내 사진과 예식 정보로 바꿔줘.
기존 디자인·폰트·모션·섹션 순서는 유지해줘.
내 저장소 사본에서 작업하고, 원본 템플릿은 변경하지 마.

[정보]
신랑 / 신부:
예식일(연·월·일) / 요일:
예식 시간(한국 시간):
장소 / 층 / 홀:
도로명 주소:
초대 문구:
신랑측 은행 / 계좌 / 예금주:
신부측 은행 / 계좌 / 예금주:
지도 링크(네이버 / 카카오 / 티맵):
지하철 / 버스 / 주차 안내:
구글폼 응답자 링크(아직 없으면 미연결):

[첨부 이미지]
카드 이미지:
초대글 배경 이미지:
갤러리 이미지 1~6:
약도 이미지:

실제 파일을 읽은 뒤 수정해줘. 없는 파일이나 빈 정보를 임의로 만들지 마.
사진은 원본 비율을 유지하고, 문구가 얼굴을 가리지 않는지 확인해줘.
config만 바꾸고 끝내지 말고, HTML·JS에 직접 들어간 이름·날짜·시간·달력·참석 안내·메타정보도 찾아 일치시켜줘.
예식일의 요일·달력의 시작 요일·일수·D-day가 한국 시간 기준으로 맞는지 확인해줘.
수정한 파일, 확인한 동작, 미확인·미연결 항목을 구분해 알려줘.
확인하지 못한 것을 확인했다고 말하지 마.
```

AI가 작업 환경에 접근할 수 없다고 하면 파일을 수정했다고 간주하지 마세요. 수정 파일 또는 실제 저장소 변경 내역을 받아 확인합니다.

## 3단계: 정보 확인

- 첫 화면, 달력, 참석 안내의 날짜·시간이 모두 같나요?
- 이름과 장소가 예시값으로 남아 있지 않나요?
- 계좌번호와 예금주가 맞나요?
- 주소 복사와 각 지도 링크가 올바른 장소를 가리키나요?
- 교통·주차 안내가 예식장의 최신 안내와 같나요?
- 참석 링크가 없을 때 전달 완료로 보이지 않나요?

현재 개발 중인 예시는 날짜·시간과 달력 일부가 코드에 직접 들어 있습니다. 배포용 템플릿이 정보 한 파일만으로 갱신되도록 정리됐는지는 공개 전 안내자가 확인해야 합니다. 정리 전에는 ‘config 한 파일만 바꾸면 모두 끝난다’고 안내하지 않습니다.

## 4단계: 변경을 GitHub에 저장

AI가 파일을 바꿨더라도 GitHub에 자동으로 반영됐다고 가정하지 마세요.

```text
수정한 청첩장 파일을 내 저장소에 커밋·푸시해줘.
변경 내용을 먼저 확인하고, 기존 사용자 파일을 지우거나 강제로 덮어쓰지 마.
푸시한 브랜치와 커밋을 알려줘. 푸시 권한이 없으면 필요한 수동 단계를 안내해줘.
```

AI가 푸시하지 못하면 수정 파일을 GitHub에 업로드하고 저장합니다. 메인 파일과 이미지 경로가 최상위 기준으로 맞는지 확인하세요.

## 완료 기준

- [ ] 카드·흑백 일러스트·사진 6장이 내 이미지로 바뀌었다.
- [ ] 날짜·시간·이름이 화면 전체에서 일치한다.
- [ ] 약도와 교통 안내를 확인했다.
- [ ] 변경 내용이 내 GitHub 저장소에 저장됐다.
- [ ] 아직 미연결인 기능을 알고 있다.

# 4. 참석 응답 폼 만들고 연결하기

RSVP는 하객의 참석 여부를 미리 받는 기능입니다. 버튼과 입력 화면이 보이는 것만으로 응답이 저장되지는 않습니다.

이 코스에서는 **하객이 구글폼에 입력 → 예비부부가 구글시트에서 확인**하는 방식을 사용합니다.

> 현재 예시 사이트의 내부 입력폼은 미리보기입니다. 실제 응답 저장과 연결되지 않았습니다. 자료 공개 전에 내부 미리보기를 거치지 않고 구글폼으로 이동하는 경로를 완성·검증해야 합니다. 이미 입력한 내용을 구글폼에 자동으로 넘기는 기능도 현재는 없습니다.

## 1단계: 내 소유의 구글폼 만들기

Google 계정에 로그인하고 새 설문지를 만듭니다. 제목은 ‘서준·지우 결혼식 참석 안내’처럼 알아보기 쉽게 씁니다. 아래 설명을 내 정보로 바꿔 넣으세요.

```text
저희의 시작을 함께해 주셔서 감사합니다.
더 편안하게 모실 수 있도록 참석 여부를 알려주세요.

예식일: [날짜와 시간]
장소: [예식장·홀]
응답 마감: [날짜]
응답 변경 문의: [담당자 연락 방법]
```

[캡처: 새 폼 생성 → 제목·설명 입력]

## 2단계: 필요한 질문만 추가

| 질문 | 추천 형식 | 필수 여부 |
|---|---|---|
| 어느 측 하객인가요? | 신랑측 / 신부측 단일 선택 | 필수 |
| 참석하시나요? | 참석 / 불참 단일 선택 | 필수 |
| 성함 | 짧은 답변 | 필수 |
| 식사 여부 | 식사함 / 안 함 / 미정 | 참석자에게만 |
| 동행인 수(본인 제외) | 숫자, 0 이상 | 참석자에게만 |
| 연락처 | 짧은 답변 | 꼭 필요할 때만 |
| 동행인 성함 | 짧은 답변 | 꼭 필요할 때만 |
| 전세버스 탑승 여부 | 탑승 / 미탑승 | 버스를 운영할 때만 |

불참자에게 식사·버스 질문을 강제로 입력시키지 않도록 섹션을 나누고 답변에 따른 이동을 설정합니다. 정확한 메뉴 위치는 최신 화면 캡처로 안내합니다.

내부 입력폼 예시는 연락처·버스 질문을 포함하지만, 구글폼에 그대로 모두 넣을 필요는 없습니다. 실제 운영에 필요한 정보만 받으세요.

## 3단계: 개인정보 안내와 동의

다음은 채워 넣을 항목의 예시이며, 그대로 게시하는 완성 약관은 아닙니다. 실제 수집 항목과 보관 방식에 맞춰 작성하세요.

```text
수집·이용 목적: 결혼식 참석 인원 및 [식사/버스 등 실제 목적] 확인
수집 항목: [실제로 받는 항목만 작성]
보관 기간: [명확한 종료일 또는 기간]
관리 담당 및 문의: [연락 방법]
동의 거부 안내: [동의하지 않을 때 적용할 대체 연락 방법 등]
```

Google 서비스를 통한 처리와 보관 위치 등 필요한 고지 사항도 실제 이용 조건에 맞춰 확인하세요. 동행인의 개인정보를 받는다면 전달하는 사람이 해당 동행인에게 알리고 동의를 얻도록 안내하세요. 이름과 연락처를 불필요하게 공개하지 않습니다.

## 4단계: 구글시트 연결

1. 폼의 응답 관리 화면을 엽니다.
2. 스프레드시트로 연결하는 기능을 선택합니다.
3. 내 계정에 새 응답 시트를 만듭니다.
4. 접근 권한은 응답을 관리할 사람에게만 부여합니다.
5. 응답 결과를 공개하는 설정이 켜져 있지 않은지 확인합니다.

[캡처: 응답 탭 → 시트 연결 → 테스트 응답 행]

## 5단계: 응답자용 링크 확인

폼의 공유 기능에서 **응답하는 사람에게 제공할 링크**를 복사합니다. 편집 링크나 응답 시트 주소를 청첩장에 넣지 마세요.

시크릿 창에서 링크를 엽니다. 로그인 없이 응답받을 계획이라면 실제로 로그인 요구가 없는지 확인해야 합니다. 조직 내부 제한·파일 업로드 질문 등 일부 설정은 로그인을 요구할 수 있습니다. 설정 이름만 보고 판단하지 마세요.

## 6단계: 청첩장에 연결

응답자 링크를 AI에게 전달합니다.

```text
청첩장의 실제 참석 응답 경로를 이 구글폼으로 연결해줘.
응답자용 링크: [링크]

메인 카드의 참석 안내 버튼과 하단 참석 버튼에서 구글폼을 열 수 있게 해줘.
사이트 내부의 미리보기 입력폼을 먼저 작성하게 해서 같은 정보를 두 번 입력하지 않도록 해줘.
내부 입력값을 자동 전송하는 연동이 없다면 있다고 말하지 마.
실제 제출은 구글폼에서 이루어진다고 사용자가 알 수 있게 해줘.
그 외 디자인은 유지하고 수정 후 확인한 것과 미확인 항목을 구분해줘.
```

설정 파일에서는 `rsvpUrl`에 응답자 링크를 넣습니다. 현재 예시 구현은 URL을 넣는 것만으로 내부 미리보기 단계가 없어지지는 않으므로 위 경로 수정도 필요합니다.

## 7단계: 전달과 저장을 끝까지 테스트

- [ ] 청첩장 메인 카드에서 응답 폼으로 갈 수 있다.
- [ ] 하단 버튼에서도 응답 폼으로 갈 수 있다.
- [ ] 시크릿 창과 실제 휴대폰에서 필요한 접근 범위로 열린다.
- [ ] 가짜 이름으로 참석·불참을 각각 제출했다.
- [ ] 구글폼에 제출 완료 화면이 나온다.
- [ ] 내 구글시트에 두 응답이 실제로 저장됐다.
- [ ] 불참자는 불필요한 질문을 건너뛴다.
- [ ] 응답 변경 방법과 문의처를 안내했다.
- [ ] 테스트 응답을 삭제했다.

이 항목을 모두 확인한 뒤 참석 기능이 작동한다고 안내하세요. 실제 하객 개인정보로 테스트하지 않습니다.

# 5. Netlify에 배포하기

배포는 파일을 인터넷에서 열리는 웹페이지로 만드는 과정입니다. GitHub에 저장한 청첩장과 Netlify를 연결하면 이후 수정도 자동으로 배포할 수 있습니다.

## 시작 전

- 내 GitHub 저장소에 수정한 `index.html`과 이미지가 있어야 합니다.
- 배포 대상 브랜치를 확인합니다. 이 자료는 `main`을 기준으로 안내합니다.
- Netlify의 현재 무료 요금제·사용량 기준을 확인합니다.

## 1단계: Netlify에 GitHub 연결

1. Netlify에 가입하거나 로그인합니다.
2. Git 저장소를 가져와 새 프로젝트를 만드는 경로를 선택합니다.
3. GitHub를 선택하고 필요한 저장소의 접근 권한을 허용합니다.
4. 내 청첩장 저장소를 선택합니다. 비공개 저장소도 연결할 수 있습니다.

[캡처: 새 프로젝트 → GitHub 연결 → 저장소 선택]

화면의 메뉴 이름은 바뀔 수 있습니다. 자료를 제작할 때 실제 화면으로 버튼명을 확정합니다.

## 2단계: 배포 설정

현재 템플릿은 별도의 빌드 과정이 없는 HTML·CSS·JS 사이트입니다.

| 설정 | 이 템플릿 기준 |
|---|---|
| 배포 브랜치 | main |
| Base directory | 별도 하위 폴더를 지정하지 않음 |
| Build command | 비움 |
| Publish directory | 저장소 루트 `.` |
| 비밀키·환경변수 | 기본 기능에는 필요 없음 |

`index.html`이 하위 폴더 안에 있다면 그대로 적용하지 말고 실제 폴더 구조를 먼저 확인하세요. 과거 다른 프로젝트 설정을 복사하지 않습니다.

[캡처: 빌드 설정과 게시 폴더 → 배포 시작]

## 3단계: ‘현재 게시된 버전’ 확인

배포 목록에서 다음을 확인합니다.

1. 내가 수정한 최신 커밋이 새 배포에 표시되나요?
2. 그 버전에 Published가 표시되나요?
3. 실제 게시 파일 목록에 `index.html`이 있나요?

우리가 직접 겪은 문제는 ‘README만 있던 이전 커밋’이 게시된 채 새 배포 행만 추가된 상황이었습니다. 새 배포가 처리됐다는 것과 현재 사이트에 게시됐다는 것을 구분해야 합니다.

최신 버전이 게시되지 않았다면 해당 배포 상세의 상태·메시지와 자동 게시 설정을 확인합니다. 필요할 때 게시 기능을 사용하되, 매번 수동 게시가 필요하다고 가정하지 마세요.

## 4단계: 기본 사이트 주소 열기

예를 들어 다음과 같은 주소가 생깁니다.

```text
내프로젝트.netlify.app
```

특정 배포의 고정 주소는 그 버전만 가리킵니다. 수정 후에도 같은 주소를 공유하려면 프로젝트의 기본 사이트 주소를 사용하세요. 도메인 변경은 공유 전에 결정합니다. 링크를 보낸 뒤 바꾸면 기존 링크가 깨질 수 있습니다.

## 5단계: 로그인 없이 열리는지 확인

휴대폰 시크릿 창에서 사이트 주소를 엽니다.

- 청첩장이 바로 열리면 로그인 없이 접근할 수 있는 상태입니다.
- Netlify 로그인을 요구하면 사이트의 접근 보호·프로젝트 공개 설정을 확인합니다.

우리 테스트에서는 Netlify 화면의 Private 표시와 Make public 설정을 확인한 뒤 외부 접근이 가능해졌습니다. 사용자 계정·프로젝트 설정에 따라 다를 수 있으므로 실제 시크릿 창 응답을 기준으로 판단하세요.

**GitHub 저장소를 Public으로 바꿀 필요는 없습니다.** 저장소 접근 권한과 웹사이트 접근 권한은 별개입니다.

## 수정은 어떻게 반영하나요?

파일 수정 → GitHub 커밋·푸시 → Netlify 새 배포 → 최신 커밋 Published 확인 → 기본 주소에서 확인 순서입니다.

GitHub 연동 방식에서는 매번 ZIP을 올리지 않습니다. 자료의 기본 경로와 폴더 수동 업로드 경로를 섞지 마세요.

## 완료 기준

- [ ] 최신 수정 커밋이 Netlify에 게시됐다.
- [ ] 기본 사이트 주소를 알고 있다.
- [ ] 휴대폰 시크릿 창에서 로그인 없이 열린다.
- [ ] 사진과 폰트가 나오고 주요 버튼이 작동한다.

# 6. 공유 전 최종 점검

PC에서 열리는 것과 하객이 휴대폰·카카오톡으로 보는 것은 다를 수 있습니다. 아래를 직접 확인한 뒤 공유하세요.

## 정보

- [ ] 이름·예식일·요일·시간·예식장·홀·주소가 정확하다.
- [ ] 카드, 달력, 참석 안내의 날짜·시간이 일치한다.
- [ ] 예시 이름과 가상 계좌가 남아 있지 않다.
- [ ] 교통·주차·지도 링크가 실제 장소에 맞다.

## 휴대폰 동작

- [ ] 첫 화면 아래가 잘리지 않는다.
- [ ] 주소창이 접히고 펼쳐져도 화면이 어색하지 않다.
- [ ] 위→아래와 아래→위로 모두 스크롤해 봤다.
- [ ] 타이틀·초대글이 최종 폰트로 표시된다.
- [ ] 카드에서 참석 안내가 열린다.
- [ ] 갤러리 사진 6장을 모두 열 수 있다.
- [ ] 확대 보기의 넘기기·닫기가 작동한다.
- [ ] 계좌와 주소가 실제로 복사된다.
- [ ] 사진이 찌그러지지 않고 얼굴이 잘리지 않는다.
- [ ] iPhone과 Android 등 서로 다른 기기에서도 확인했다.

가능한 기기에서만 확인했다면 확인하지 못한 기기는 미확인으로 남깁니다. 한 기기 결과를 전체 기기 검증으로 표현하지 마세요.

## 참석 응답

- [ ] 하단 참석 버튼이 올바른 폼을 연다.
- [ ] 시크릿 창에서 응답할 수 있다.
- [ ] 제출 완료를 확인했다.
- [ ] 구글시트에 테스트 응답이 저장됐다.
- [ ] 테스트 응답은 삭제했다.

## 공유 범위와 개인정보

- [ ] 사이트에 관리자 키·비밀번호·하객 응답 파일이 없다.
- [ ] 공개 사진·연락처·계좌를 당사자와 확인했다.
- [ ] 링크를 아는 사람은 정보를 볼 수 있음을 이해했다.
- [ ] 검색 제외 설정이 접근 차단을 보장하지 않음을 이해했다.
- [ ] 사이트 접속에 Netlify 로그인이 필요하지 않다.

## 카카오톡 미리보기

내 카카오톡 또는 테스트 대화방에 **최신 기본 주소**를 보내 제목·설명·이미지를 확인합니다. OG 태그는 링크 미리보기의 제목과 그림을 지정하는 정보입니다.

AI에게 다음과 같이 요청할 수 있습니다.

```text
이 청첩장의 카카오톡 공유 미리보기를 설정해줘.
제목: [신랑·신부 결혼합니다]
설명: [예식일·시간·장소]
기본 사이트 주소: [주소]
미리보기 이미지: [배포 가능한 이미지 파일]

정적 HTML의 OG 태그와 실제 공개 이미지 URL을 확인해줘.
링크 크롤러를 막는 robots.txt나 비밀번호 설정을 임의로 추가하지 마.
직접 카카오톡 화면을 확인할 수 없다면 설정 확인과 실제 표시 확인을 구분해줘.
```

예시 코드에 제목·설명이 있어도 OG 이미지·공개 URL까지 완성됐다고 가정하지 마세요. 미리보기가 갱신되지 않으면 캐시일 수 있으므로 최신 URL과 크롤러 접근부터 확인합니다.

## 발송 문구 예시

```text
안녕하세요, [이름]님.
저희가 [날짜]에 결혼합니다.
소중한 날 함께해 주시면 감사하겠습니다.

청첩장: [기본 사이트 주소]
참석 여부는 [마감일]까지 알려주시면 감사하겠습니다.
```

개인화된 `?to=이름` 기능은 현재 템플릿에 구현돼 있지 않습니다. 이름을 붙인다고 자동으로 바뀐다고 안내하지 마세요.

# 7. 막혔을 때 확인하기

## 사이트가 Not Found / 404로 떠요

GitHub를 Public으로 바꾸기 전에 아래 순서로 확인하세요.

1. 저장소에 README만 있는 것은 아닌가요?
2. 저장소 루트에 `index.html`이 있나요?
3. 수정 파일을 커밋·푸시했나요?
4. Netlify가 같은 저장소·브랜치를 읽고 있나요?
5. Publish directory가 실제 파일 위치와 같나요?
6. 최신 커밋에 Published가 표시되나요?
7. 이전 배포 고정 주소를 보고 있지는 않나요?

## 사이트가 Netlify 로그인을 요구해요

시크릿 창에서도 같은지 확인하고 Netlify의 사이트 접근 보호·공개 설정을 확인합니다. GitHub 비공개 저장소를 공개로 바꾸는 것으로 해결하려 하지 마세요.

## 수정했는데 예전 화면이에요

로컬/AI 작업 공간의 파일, GitHub 최신 커밋, Netlify 현재 게시 커밋을 순서대로 비교합니다. 그다음 기본 주소를 새로고침합니다. 예전 고정 배포 URL은 새 버전으로 바뀌지 않습니다.

## 사진이 안 나와요

파일이 실제로 업로드됐는지, 파일명 대소문자와 경로·확장자가 일치하는지 확인합니다. PC의 파일 경로를 넣으면 다른 사람에게 보이지 않습니다.

AI 채팅에서 보이는 이미지가 자동으로 저장소에 들어가는 것은 아닙니다. 생성 파일을 실제 배포 폴더에 저장했는지 확인하세요.

## 손글씨가 바뀌거나 처음에 기본 폰트가 보여요

폰트 파일의 경로·로딩 상태를 확인합니다. 현재 예시는 폰트 미리 불러오기와 로딩 후 타자기 시작을 적용했습니다. 다른 폰트로 바꾸면 파일 경로·선언·preload도 함께 수정해야 합니다.

폰트 사용·재배포 권한은 글꼴마다 다릅니다. 내려받았다는 이유만으로 템플릿에 번들할 수 있다고 판단하지 마세요.

## 화면이 잘리거나 스크롤이 답답해요

기기, 브라우저, 주소창이 보이는지, 스크롤 방향을 함께 기록합니다. 글자 확대 설정과 펼친 계좌·교통 안내 상태도 확인하세요. 문구가 길어졌다면 한 화면에 억지로 넣기보다 글을 줄이거나 콘텐츠 높이를 허용해야 할 수 있습니다.

## 참석 입력은 했는데 전달이 안 돼요

현재 내부 폼은 미리보기입니다. 실제 구글폼 연결과 응답 저장 테스트가 필요합니다. 링크만 연결한 상태에서는 내부 입력값이 자동 전달되지 않습니다. 같은 내용을 두 번 입력하게 만들지 않도록 실제 배포 경로를 정리하세요.

제출 완료 화면과 구글폼 응답 탭·연결 시트를 확인하기 전에는 전달됐다고 간주하지 않습니다.

## AI에게 오류를 물어볼 때

```text
모바일 청첩장에서 아래 문제가 생겼어. 원인을 확인하고 필요한 부분만 수정해줘.

사이트 주소:
기대했던 동작:
실제 동작:
기기 / 브라우저:
재현 순서:
오류 메시지:
최근 수정 내용:

기존 디자인과 정상 동작은 유지해줘.
파일·로그를 읽지 못하면 읽었다고 하지 마.
추측과 확인된 원인을 구분해줘.
수정 후 실제 확인한 범위와 미확인 범위를 알려줘.
```

스크린샷과 로그에서 전화번호·계좌·하객 이름·관리자 키는 가립니다. 오류 메시지는 내용을 바꾸지 말고 필요한 부분만 그대로 전달하세요.

# 8. 예식 후 정리하기

사이트를 안 쓴다고 사진과 하객 응답이 자동으로 삭제되지는 않습니다. 사전에 정한 기간에 정리하세요.

## 응답 정리

1. 필요한 응답 자료만 안전하게 백업합니다.
2. 구글폼의 응답 수집을 종료합니다.
3. 보관 기간이 끝나면 폼·연결 시트·다운로드한 사본의 개인정보를 삭제합니다.
4. 함께 관리한 사람이 있다면 공유 사본과 권한도 확인합니다.

폼만 삭제해도 시트나 내려받은 파일은 남을 수 있습니다.

## 사이트·사진 정리

1. 청첩장을 비공개로 바꾸거나 배포를 종료합니다.
2. 기본 주소뿐 아니라 과거 배포 주소의 접근 상태도 확인합니다.
3. Netlify의 남은 배포·이미지와 GitHub 저장소·수정 기록의 개인정보를 확인합니다.
4. 공개 저장소였다면 다른 사람이 만든 사본까지 회수할 수 없다는 점을 염두에 둡니다.
5. 자료를 보존하고 싶다면 개인정보를 뺀 버전을 따로 만듭니다.

현재 파일에서 사진을 지웠다고 과거 Git 기록과 배포본에서까지 지워진 것은 아닙니다. 삭제 범위를 확인하고, 필요한 경우 서비스의 공식 삭제 절차를 이용하세요.

## 마지막 확인

- [ ] 참석 응답 수집을 종료했다.
- [ ] 정한 기한에 응답과 사본을 정리했다.
- [ ] 사이트와 과거 배포의 공개 상태를 확인했다.
- [ ] 사진·연락처·계좌가 남은 위치를 확인했다.
- [ ] 도메인·유료 옵션이 있다면 자동 결제도 확인했다.

# 심화. AI로 내 취향에 맞게 수정하기

기본 코스를 완성한 뒤 한 번에 한 가지씩 바꿉니다. 지금 작동하는 커밋을 기록하고 화면을 캡처해두면 돌아오기 쉽습니다.

## 수정 요청은 세 부분으로

1. 유지할 것
2. 바꿀 것
3. 확인할 것

```text
현재 청첩장에서 아래 항목만 수정해줘.

[유지]
섹션 순서, 사진, 참석 폼 연결, 지도·계좌 복사, 모바일 대응은 유지.

[변경]
[예: 버튼 모서리만 조금 둥글게 / 초대 문구만 크게 / 배경색만 변경]

[확인]
작은 화면에서 글자나 사진이 잘리지 않는지 확인해줘.
모바일 터치와 PC 클릭을 확인하고, 모션을 줄인 설정에서도 사용할 수 있게 해줘.
확인한 것과 확인하지 못한 것을 구분해줘.
```

‘전체적으로 더 예쁘게’보다 변경 범위를 구체적으로 적으면 반복 수정이 줄어듭니다. 서로 다른 기기의 캡처가 있으면 함께 전달하세요.

## 사진을 일러스트로 바꾸고 싶다면

권한이 있는 사진을 사용하고 사진 속 인물에게 AI 서비스 전달과 공개에 대한 동의를 받습니다. 이용하는 도구가 이미지 편집을 지원하는지 확인하세요.

```text
첨부 사진을 모바일 청첩장에 쓸 [수채화/연필화]로 변환해줘.
두 사람의 얼굴 특징·옷·포즈·구도는 최대한 유지해줘.
글자·로고·장식은 새로 추가하지 마.
카드에 쓸 세로 이미지이며 인물의 손과 발이 잘리지 않게 해줘.
얼굴·손·소품이 달라질 수 있으니 결과는 내가 검수할게.
첨부 사진을 볼 수 없으면 먼저 알려줘.
```

생성한 결과는 원본과 완전히 같지 않을 수 있습니다. 얼굴·손·반지·꽃·간판을 직접 확인하세요. 결과 이미지가 채팅에 보이지 않으면 생성 파일 자체가 있는지 확인하고, 파일을 배포 폴더에 저장해야 사이트에 나타납니다.

## 처음부터 새 디자인을 만들고 싶다면

기본 템플릿과 별도 사본에서 진행하세요. 참고 자료는 분위기를 설명하는 용도로 쓰고 다른 작품의 문구·사진·구도를 그대로 복제하지 않습니다.

디자인 시안 → 한 화면 구현 → 모바일 확인 → 나머지 섹션 확장 → 실제 정보·폼 연결 → 배포 테스트 순서로 작업하세요. 처음부터 모든 기능을 한 번에 만들라고 요청하지 않는 편이 수정 범위를 관리하기 쉽습니다.
