# 무료 나눔 자료 작성 시 반영할 배포 경험

## 대상과 배포 경로

- 이 청첩장은 비개발자에게 무료 나눔 자료로 제공할 예시다. 향후 유료 자동화 서비스의 배포와 별개로 안내한다.
- Netlify와 Vercel 모두 GitHub 연동이 가능하다. Netlify도 비공개 저장소를 연결할 수 있다.
- GitHub 연동 배포에는 ZIP이 필요 없다. 폴더 수동 업로드와 GitHub 자동 배포는 각각 별도 경로로 설명한다.
- GitHub 저장소의 공개 여부와 배포된 웹사이트의 공개 여부는 다르다. 사이트를 보기 위해 저장소를 Public으로 변경할 필요가 없다.

## 실제 겪은 혼란 (2026-11-03)

1. 저장소에 README만 있는 최초 커밋 `943c85c`를 연결해 배포했다. 청첩장 코드가 없어 사이트에서 Not Found가 발생했다.
2. 클라우드 작업 공간에 생성한 코드는 GitHub에 자동 반영되지 않는다. 커밋·푸시가 필요하다.
3. 청첩장 코드 커밋 `57a3e7f`를 main에 푸시했다.
4. 이후 Netlify 목록 스크린샷에는 새 커밋의 배포 행이 있었지만 `Published` 표시는 여전히 이전 커밋에 붙어 있었다.
5. 새 배포 상세에서 Publish deploy를 찾도록 안내했다. 실제 버튼 위치, 게시 완료 여부, 자동 게시가 이루어지지 않은 원인은 아직 확인되지 않았다. 수동 게시가 항상 필요하다고 단정하지 않는다.

## 공유자료에 필요한 단계별 안내

- 실제 화면 캡처와 눌러야 할 버튼 이름을 함께 제공한다. 메뉴명은 작성 당시 UI에서 다시 확인한다.
- 작업 파일 생성 → GitHub 커밋·푸시 → Netlify 배포 → 현재 게시 버전 확인 → 실제 링크 기능 점검까지 끊김 없이 안내한다.
- 저장소 루트에 index.html이 있는지 확인한다. 현재 프로젝트는 별도 빌드 명령이 없고 배포 폴더는 루트다. Netlify의 Base directory 등 관련 설정도 실제 화면에서 검증한다.
- Deploys에서 최신 커밋과 Published가 붙은 커밋을 비교하도록 설명한다. 배포 처리 완료와 현재 사이트 게시를 혼동하지 않게 한다.
- 특정 배포의 고정 주소와 기본 사이트 주소의 차이를 설명한다. 이전 배포 고정 주소는 새 푸시로 갱신되지 않는다.
- 404가 발생하면 저장소 공개 전환부터 시도하지 말고 게시된 커밋, 배포 파일 목록의 index.html, 배포 폴더, 열어본 URL을 확인한다.
- 자동 게시가 켜져 있는데 구버전이 게시되어 있으면 최신 배포 상세 상태와 메시지를 확인한다. 원인을 확인하기 전에는 추측을 확정 사실로 쓰지 않는다.
- 정상 화면이 뜨는 것뿐 아니라 모바일에서 카드 뒤집기, 스크롤, 갤러리 확대 등을 직접 확인한다.
- 기본 코스와 심화 코스의 배포 경로를 분리하고, 실패 시 확인할 항목을 FAQ로 제공한다.

이 기록은 공유자료 작성 시 반드시 참고한다. 호스팅 무료 한도·정책과 UI는 자료 공개 직전에 다시 확인한다.
