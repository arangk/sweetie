# 이미지 설정·예외 처리와 폰트 로딩 검증

## 변경

- 표지: config.coverImage. 표지 카드와 하단 배경이 같은 값을 사용한다.
- 초대글 일러스트: config.portraitImage. HTML의 고정 경로를 제거했다.
- 갤러리: config.gallery[].src. 비어 있거나 로딩에 실패한 사진은 버튼과 넘기기 목록에서 제외한다.
- 약도: config.location.mapImage. 경로가 비었거나 로딩에 실패하면 약도 자리만 숨긴다.
- 이미지 확장자를 강제하거나 바꾸지 않고 실제 이미지로 로딩한다. PNG, JPG, WebP 각각 검증.
- 초대글 배경이 없으면 이름·문구가 기본 배경에서도 읽히도록 글자 대비를 조정한다.
- 설정 키는 코드 호환성을 위해 유지하고 각 항목과 주석을 한국어로 설명했다.
- README의 이미지 경로 변경법도 설정 항목 기준으로 갱신했다.

## 실제 브라우저 검사

Chromium, 로컬 전용 HTTP 서버, 390×844 화면으로 확인했다.

1. 기본 이미지 6장, 표지·초대글 로딩.
2. PNG/JPG/WebP 실제 형식의 이미지를 표지·초대글·갤러리에 각각 적용.
3. 빈 경로와 존재하지 않는 파일에서 표지·초대글·하단 이미지 숨김.
4. 이미지가 없어도 하단 참석 입력폼 열기 정상.
5. 빈 사진·정상 PNG·없는 JPG·정상 JPG가 섞인 목록에서 정상 사진 2장만 표시.
6. 확대 번호 01/02 → 02/02 → 01/02 순환.
7. 기존 삭제 파일 및 모든 TTF 부재, _internal 문서 이동 상태 유지.
8. index.html/app.js/styles.css에 표지·초대글·갤러리의 고정 이미지 경로가 없음을 확인.

## 폰트

기존에는 첫 타이틀이 초대글용 대용량 손글씨 폰트까지 같이 기다렸다. 이제 첫 화면(Orbit·Parisienne)과 초대글 손글씨의 준비 Promise·표시 gate를 분리했다.

- 첫 접속: 로컬 환경의 첫 화면 폰트 준비 약 235ms.
- 손글씨 응답에 인위적으로 2500ms 지연: 첫 타이틀 시작 약 192ms. 손글씨는 준비 전 숨기고 준비 후 타자기 시작.
- 손글씨 응답에 4400ms 지연: 3500ms 제한 후 대체 글꼴로 고정. 늦은 최종 폰트 응답이 와도 화면에서 글꼴 교체 없음.

위 수치는 로컬 테스트 결과이며 Netlify 외부망·실제 iPhone Safari의 실측 속도가 아니다. 느린 네트워크에서 준비 시간을 완전히 없애는 것은 아니지만, 손글씨 다운로드 때문에 첫 화면이 기다리는 문제와 뒤늦은 글꼴 교체는 검증했다.
